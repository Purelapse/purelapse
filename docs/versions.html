Version history

What has changed.

The key changes of every version at a glance. Every detail is in the full changelog (German).

Current

2.47.0-beta

27 November 2026
Download AppImageWindows (.exe)Release on GitHub

RapidRAW joins as the fifth engine – Purelapse develops with it without opening RapidRAW. The gallery now shows keyframes in the engine's look, and the video carries the engine's code in its name.

RapidRAW 1.6 or newer: only from there can RapidRAW develop without a window. At least one frame of the sequence must be edited in RapidRAW – the look for all others comes from it.

New

  • RapidRAW as an engine: edit keyframes in RapidRAW and mark them with 5 stars, then pass 1 and pass 2. All controls blend smoothly – HSL, colour grading and curves included; masks and AI retouching switch halfway. The whole sequence develops in one call, with RapidRAW as a Flatpak or on Windows too.
  • Gallery in the engine's look: keyframes show what RapidRAW, ART, RawTherapee or darktable make of them even before pass 2 – developed in the background, the program stays responsive. After pass 2 the gallery shows the developed frames.
  • Engine in the video name: e.g. …_2160p_25fps_RT.mp4 – so videos of the same sequence from different engines sit side by side.
  • Real preview shows it is working: until the engine's image arrives, the approximation is blurred and the note pulses gently.

Fixed

  • Two screens: the start dialog and other dialogs appear on the main window's screen.
  • Windows: cancelling stops the engine along with every process it started itself.
  • ART: the scaled-down preview always works in pixels, even if the keyframe's resize is set to centimetres.

2.46.1-beta

27 November 2026
Release on GitHub

Polish for 2.46: a freshly computed, clean icon – also as the Windows .exe symbol – and the switch for 16-bit intermediate images now sits with the video settings.

Changed

  • 16-bit intermediates with the video: the switch now sits where you set up rendering, with a note on when it helps – banding in smooth gradients such as a clear sky. While it is on, it shows in warning colour with the space needed, and in the summary.
  • New icon: computed exactly from its geometry, without fringes; tuned separately for small sizes. The Windows .exe gets its own symbol in all sizes.

Website

  • Lightroom trademark notice in the footer.

2.46.0-beta

26 November 2026
Release on GitHub

Purelapse now runs on Windows too – as a single .exe, no installation. Plus Lightroom Classic as a fourth engine, engines from Flatpak are detected on Linux, and darktable 5 is fully supported.

Windows says “Windows protected your PC”? The .exe is not signed. Continue via “More info” → “Run anyway”.

New

  • Windows 10/11: a single file with everything Purelapse needs. ART, RawTherapee and darktable are found in their usual install folders. Same workflow as on Linux.
  • Lightroom Classic as an engine: Purelapse writes exposure and keyframe transitions into the XMP files – all sliders, white balance and tone curves are blended smoothly. Lightroom reads them and exports, Purelapse builds the video from the export and fine-adjusts the residual flicker.
  • Engines from Flatpak (Linux): RawTherapee, ART and darktable from Flathub are detected and started with exactly the folder permissions a run needs.

Fixed

  • darktable 5: the exposure (module version 7) was not recognised – deflickering overwrote black level and highlight preservation, keyframe exposures were lost. White balance, denoise and haze removal from darktable 5 are now blended smoothly too, even mixed with keyframes from darktable 4.
  • Videos now carry their colour space (BT.709) with newer FFmpeg versions too – primaries and transfer were missing there before.
  • Crash when closing while the gallery was still reading thumbnails.

2.45.0-beta

25 November 2026
Release on GitHub

“Auto-optimise” makes the frame pleasing in one click – with new controls for highlights, shadows and vibrance in all three engines. Plus: deflickering can be switched off, and in 24-hour timelapses the night can drop out of the video.

Saved a keyframe via the quick settings and the frame turned orange or blue? If the profile used the camera white balance, older versions saved its placeholder (6504 K) as a custom white balance. Set that keyframe's white balance back to “Camera” in the engine – or pick a suitable temperature in the dialog.

New

  • Recover highlights, lift shadows, vibrance: three new quick settings that work locally – ART via the tone equalizer, RawTherapee via shadows/highlights, darktable via “shadows and highlights”. The same slider value does roughly the same in all three engines.
  • Deflickering optional: without the tick the timelapse keeps the camera's brightness – keyframes, camera move, telemetry and effects still work. For RAW, pass 1 then only prepares the profiles. Remembered per folder.
  • Remove night: in 24-hour timelapses, frames below an adjustable scene brightness drop out of the video – measured including the EXIF exposure, so it also works with auto exposure. The threshold can be dragged in the chart, the night is shaded grey. The whole series is still deflickered so the twilight is right.

Changed

  • “Auto-optimise” aims for a pleasing result: first highlights down and shadows up, then punch for the midtones, colour via vibrance. It now measures the engine's image instead of the approximation. Night scenes stay dark, at high ISO the shadows are lifted more gently.
  • darktable: shadows and highlights and colour balance rgb are blended smoothly even if they exist in only one keyframe.

Fixed

  • Real preview orange, approximation normal: the placeholder white balance of a profile using the camera white balance was saved as a custom one. Now colour temperature stays unticked in that case; its starting value is computed from the RAW.
  • −, + and “neutral” next to the sliders now always follow the tick; optimising twice gives the same result.

2.44.1-beta

25 November 2026
Release on GitHub

Fix for 2.44.0: deflickering stays stable even with lots of clipped highlights – candlelight or lamps in the frame, especially with camera motion.

If pass 2 flickered with 2.44.0 or older: run pass 1 and pass 2 once more. Pass 1 discards the faulty corrections of the old run.

Fixed

  • Recalibration ran away: when almost every area clipped at some point in a sequence, a brightened frame measured darker – and kept being brightened. Single frames jumped by nearly one stop. The measurement now compares with neighbouring frames and stays stable; in the real-world case frame-to-frame flicker dropped to a twentieth.
  • Old recalibration corrections are discarded after a new pass 1 instead of flowing into every following run.
  • Keyframes were briefly counted twice when reloading; “Open folder” now follows a folder change.

A calmer, more professional look inspired by DaVinci Resolve – and the folder picker shows every image in a scrollable grid.

2.43.1-beta

22 November 2026
Release on GitHub

Fix for 2.43.0: keyframes match everywhere again after switching the engine.

If you switched between darktable and RawTherapee or ART: open the folder again and check the stars in the gallery. They now show every image that counts as a keyframe during development.

Fixed

  • Keyframes after switching the engine: the header said e.g. “8 keyframes” while the filter showed 4 – and four images were developed as keyframes without being visible. The gallery now re-reads its stars when switching and reports differences in the log.
  • Cancelling a preview no longer leaves a working folder behind.

Internal

  • The tests now also run on machines with an NVIDIA card and with Python packages in ~/.local; the summary no longer misses failures.

2.43.0-beta

22 November 2026
Release on GitHub

A folder picker with image preview – and everything Purelapse creates is now kept tidy in a “Purelapse” subfolder.

When upgrading: when you open a folder from an older version, Purelapse moves videos, Deflickered_JPG and measurement files into the “Purelapse” folder once. Other files stay untouched, nothing is overwritten.

New

  • Folder picker with preview: the dialog shows the number and type of images and six previews spread across the sequence – you see at once whether it's the right timelapse. The dialog is much larger.

Changed

  • Everything in one place: videos, developed frames, measurement data and logs live in the “Purelapse” subfolder of the image folder. Only the engine's sidecar files stay next to the images.
  • Location “Purelapse folder in the image folder” is the recommended default; “Open folder” and “Reset” use the new place.

Website

  • Mastodon account linked; the technical section describes the new layout.

2.42.0-beta

20 November 2026
Release on GitHub

The biggest overhaul so far: more accurate measurement, darktable on a par with ART and RawTherapee, cleaner videos. Includes the unpublished interim versions 2.40 and 2.41.

When upgrading: the measurement has changed – run pass 1 and pass 2 again for ongoing projects. Old settings files are migrated on first start.

Image quality

  • The sun and clipped highlights no longer distort the measurement. Residual flicker with the sun in frame: from up to 0.05 EV down to 0.0005 EV.
  • Recalibration judges clipped areas across the whole sequence and no longer creates flicker where there was none.
  • Camera move accurate to fractions of a pixel, without judder, with gentle acceleration and braking.
  • Video colours to the HD standard BT.709 and more thorough encoder settings.
  • New: HEVC 10 bit (CPU and NVIDIA) and 16-bit intermediate images against banding in the sky.

darktable

  • Keyframes carry the complete module stack – more than 60 modules from white balance to filmic are blended smoothly.
  • Quick settings (brightness, contrast, saturation, sharpening) with a real preview.
  • darktable-cli develops with up to four processes at once, even while darktable is open.
  • Hot-pixel correction now works, and the deflicker value reliably ends up in the effective exposure.

Usability

  • Icons instead of text for folder, refresh, reset and settings; clearer step buttons.
  • The log is now fully available in English as well.
  • Just one configuration file instead of up to 16 separate files in the home folder.

Reliability

  • All files are written atomically; write errors stop the run with a message.
  • darktable-cli can no longer hang: time limit per frame, immediate cancel.
  • No more ghost text with motion blur and telemetry overlay.
  • About 3000 automated checks run on every change.

First public beta.

Included
